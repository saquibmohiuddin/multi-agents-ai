# Contributing Guidelines

Thank you for considering contributing to this project! By participating in this project, you agree to abide by the following guidelines.

## How to Contribute

1. **Fork the repository** and create a new branch for your feature or bug fix.
2. **Write clear, concise commit messages**. Follow the existing commit style used in the project.
3. **Ensure code follows the project's style guidelines** (see the `STYLE_GUIDE.md` if present).
4. **Add or update tests** to cover your changes.
5. **Run the test suite** locally to make sure everything passes.
6. **Submit a Pull Request** targeting the `main` branch.

## Issue Reporting

- Search existing issues before opening a new one.
- Provide a clear title and description.
- Include steps to reproduce, expected behavior, and actual behavior.
- Attach logs or screenshots if helpful.

## Pull Request Process

- **Title**: Use a descriptive title prefixed with the type of change, e.g., `feat: add new authentication flow`.
- **Description**: Explain what the PR does, why the change is needed, and any relevant background.
- **Link Issues**: Reference any related issues using `closes #<issue_number>`.
- **Review**: At least one other maintainer must approve the PR before it can be merged.

## Code Style & Quality

- Follow the existing coding conventions and linting rules.
- Use descriptive variable and function names.
- Keep functions small and focused.
- Include docstrings/comments where appropriate.

## Testing

- Write unit tests for new functionality.
- Ensure existing tests continue to pass.
- Run `npm test` (or the appropriate test command) before submitting.

## Documentation

- Update or add documentation for any new features or changes.
- Ensure README and any relevant docs are consistent with the code.

## License

By contributing, you agree that your contributions will be licensed under the project's license.

We appreciate your contributions and look forward to collaborating with you!
